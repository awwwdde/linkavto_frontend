## 1. Динамические атрибутные фильтры каталога (facets.attributes)

**Где нужно:** страница каталога `/category/:slug`, панель фильтров (левая колонка / bottom-sheet).

**Что нужно:** старый каталог (`shop/views.py` → `category.html`) показывает в сайдбаре динамические фильтры по атрибутам товаров категории: «Вязкость», «Объём», «Основа масла», «Материал», «Напряжение», «Сезонность», «Тип товара», «Тип аксессуара», «Тип инструмента», «Назначение», «Тип запчасти» и т.п. — набор зависит от категории. Нужно отдавать их фронту как единый список фасетов.

**Метод/путь:** расширить существующий `GET products/?category=...` — добавить в объект `facets` поле `attributes`:

```jsonc
"facets": {
  "manufacturers": [{ "value": "...", "label": "...", "count": 12 }],
  "product_brands": [ ... ],
  "price_min": 32000,
  "price_max": 1890000,
  "attributes": [
    {
      "code": "attr_viscosity",      // имя GET-параметра фильтра
      "label": "Вязкость",           // заголовок секции
      "options": [
        { "value": "5w-30", "label": "5W-30", "count": 42 },
        { "value": "5w-40", "label": "5W-40", "count": 18 }
      ]
    }
  ]
}
```

**Параметры фильтрации:** мультивыбор через CSV, `GET products/?...&attr_viscosity=5w-30,5w-40&attr_country=Германия`.

**Договорённость об именах:** фронт шлёт то имя, что пришло в `code`. Старый бэк использует «голые» имена (`viscosity`, `volume`, `material`, `voltage`, `season`, …) — нужно либо вернуть их как `code` напрямую (тогда фронт подстроится), либо унифицировать под `attr_*`. Что удобнее бэку — то и присылать в `code`; фронт использует `code` как есть.

**Статус:** замокано в MSW (`src/mocks/fixtures.ts` → `attributeFacetsFrom`, коды `attr_grade/side/warranty/country`), фильтрация в `handlers.ts`. Помечено `TODO(api)`.

**Профильные оси разделов (ТЗ §1).** Фронт ждёт их тем же механизмом `attributes`, но с фиксированными кодами, чтобы поднимать их в начало панели: `attr_body_type` («Тип кузова») и `attr_side` («Сторона») в кузовных категориях, `attr_side` и `attr_position` («Расположение»: Передняя/Задняя) в категориях фар и оптики. Коды нужно согласовать — см. `src/features/catalog-filters/filter-profile.ts`.

**Поле `facets.tire_wheel` больше не нужно** — параметры шин и дисков приходят обычными атрибутами (`attr_diameter`, `attr_width`, `attr_profile`, `attr_season`, `attr_pcd`, `attr_offset`, `attr_wheel_type`) и фильтруются тем же способом. Из контракта и мока удалено.

## 1а. Фильтр по подкатегориям (`category_in`) и мультивыбор в подборе по авто

**Где нужно:** панель фильтров каталога — блок «Категория» и каскад «Марка → Модель → Поколение → Модификация».

**Что нужно:**

1. `GET products/?category=<slug>&category_in=<slug1>,<slug2>` — сузить выдачу до поддеревьев перечисленных категорий (внутри списка — ИЛИ). Слаги приходят «как есть», разворот ветки в потомков — на бэке.
2. Параметры каскада принимают **несколько значений через запятую**: `?brand=lada,kia&model=...&generation=...&modification=...`. Внутри уровня — ИЛИ, между уровнями — И.

**Зачем именно так:** выбор одной категории фронт кодирует путём (`/category/legkovye/kuzov`), нескольких — `category_in` на общем предке. Так у каждой «настоящей» выдачи один канонический адрес, а комбинированные помечаются `noindex`.

**Статус:** реализовано в моке (`handlers.ts` → `applyCategoryFilter`, `applyVehicleFilters`).

## 1б. Справочники подбора по технике

**Где нужно:** каскад подбора в фильтрах и в гараже.

**Метод/путь:** `GET catalog/brands/`, `catalog/models/`, `catalog/generations/`, `catalog/modifications/`, `catalog/vehicle-classes/` — этих ручек нет в контракте §7, фронт вывел их из моделей (`CarBrand/CarModel/CarGeneration/CarModification` и аналоги для грузовых/мото/спец).

**Параметры:** `vehicle_type`, родитель уровня (`class`/`brand`/`model`/`generation`) — **необязательный и мультизначный CSV**, плюс `category=<slug>` для счётчиков.

**Поля ответа помимо `id/name/slug/vehicle_type`:**

- `products_count` — сколько товаров текущего раздела (`category`) подходит варианту. Без него пользователь выбирает вслепую и попадает в пустую выдачу;
- `is_popular` у марок и моделей — группа «Популярные» над общим списком;
- `image` у поколений (`{ thumb, card, full, alt }`) — список поколений показывается карточками с фотографией;
- у моделей/поколений — `year_start`/`year_end`, у поколений и модификаций — слаги предков (`brand_slug`, `model_slug`, `generation_slug`).

**Статус:** замокано (`src/mocks/vehicles.ts`, счётчики — `handlers.ts` → `vehicleCounts`). Фото поколений в моке рисованные.
